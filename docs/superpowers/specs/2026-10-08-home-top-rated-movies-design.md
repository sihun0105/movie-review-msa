# 홈 고평점 영화 큐레이션 설계

## 목표

홈의 박스오피스 TOP 10과 별개로 실제 볼래 사용자가 평가한 영화를 발견할 수 있게 한다. 전체 영화 목록을 프론트에서 내려받아 정렬하지 않고, 백엔드가 집계와 정렬을 담당한다.

## API 계약

- 공개 REST API: `GET /movie/top-rated?limit=12`
- gRPC: `GetTopRatedMovies(TopRatedMoviesRequest) returns (MovieDatas)`
- `limit`은 기본 12, 최소 1, 최대 24로 정규화한다.
- 기존 `MovieData` 응답을 재사용해 포스터, 제목, 감독, 장르, `averageScore`, `scoreCount`를 제공한다.
- 인증은 요구하지 않는다.

## 집계와 정렬

1. soft-delete되지 않고 점수가 존재하는 `movieScore`만 집계한다.
2. 영화별 평균 평점과 평가 수를 계산한다.
3. 평균 평점 내림차순, 평가 수 내림차순으로 후보를 고른다.
4. 후보 영화 정보를 한 번의 `Movie.findMany`로 조회한다.
5. 동률의 최종 순서는 최신 개봉일, `movieCd` 순으로 안정화한다.
6. 영화가 삭제됐거나 조회되지 않으면 해당 후보만 제외한다.

초기 서비스의 평가량을 고려해 최소 평가 수는 1개로 둔다. 카드에는 평가 수를 함께 표시해 사용자가 표본 크기를 판단할 수 있게 한다.

## 프론트엔드

- datasource/repository에 `getTopRatedMovies(limit)`를 추가한다.
- 홈 서버 컴포넌트 `TopRatedMovies`가 최대 12개를 조회한다.
- 현재 박스오피스 TOP 10의 영화 코드를 제외하고 최대 6개를 노출한다.
- 포스터, 제목, 평균 평점, 평가 수를 카드에 표시하고 상세 페이지로 연결한다.
- 결과 없음 또는 API 오류 시 섹션만 숨기며 홈 렌더링은 유지한다.
- 홈의 60초 ISR 정책을 그대로 사용한다.

## 오류와 성능

- 백엔드는 잘못된 `limit`을 안전한 범위로 정규화한다.
- 집계 쿼리와 영화 상세 쿼리는 각각 한 번만 실행한다.
- 프론트는 공개 서버 요청을 사용하며 사용자별 캐시와 섞지 않는다.
- 새 API 배포 전 프론트가 호출되지 않도록 백엔드, 프론트 순으로 배포한다.

## 검증

- movie-service: soft-delete 제외, 정렬, limit, 누락 영화 제외 테스트
- API Gateway: query 전달 테스트와 서비스 타입 검사
- 프론트: 중복 제거, 최대 6개, 빈 결과 숨김 계약 테스트
- 전체 lint/test/build와 수정 파일 200줄 상한 확인
- 운영 API 응답과 홈 카드 링크를 배포 후 확인
