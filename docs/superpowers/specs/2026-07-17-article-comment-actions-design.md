# 아티클 댓글 액션 설계

## 목표

- 영화 댓글의 `좋아요`, `싫어요`, `답글`을 한 행에 배치한다.
- 아티클 댓글에도 사용자별 좋아요/싫어요 토글과 1단계 대댓글을 제공한다.
- 아티클 댓글 삭제와 수정 상태를 영화 댓글과 같은 규칙으로 표시한다.

## 범위

- 아티클 본문 자체의 기존 좋아요/싫어요는 변경하지 않는다.
- 댓글 및 대댓글의 반응은 로그인 사용자만 변경할 수 있다.
- 대댓글의 대댓글은 허용하지 않는다.
- 활성 대댓글이 있는 삭제 부모 댓글은 `삭제된 댓글입니다.`로 유지한다.
- 삭제된 대댓글과 대댓글이 없는 삭제 부모 댓글은 목록에서 제외한다.

## 데이터 모델

`articleComments`에 `parentId`와 `isEdited`를 추가하고 자기참조 관계를 구성한다.
`ArticleCommentReaction`은 `(commentId, userno)`를 유일 키로 사용하며 `like` 또는
`dislike` 한 상태만 저장한다. 같은 반응을 다시 누르면 삭제하고, 반대 반응을
누르면 기존 행의 타입을 변경한다.

## API 계약

- 목록 요청은 선택적 JWT를 사용해 공개 조회를 유지하면서 `userReaction`을 계산한다.
- 생성 요청은 선택적 `parentId`를 받고 부모가 같은 아티클의 최상위 활성 댓글인지 검증한다.
- `POST /article/comments/:commentId/reaction`은 반응을 토글하고 최신 집계를 반환한다.
- 댓글 응답은 `replies`, `likeCount`, `dislikeCount`, `userReaction`, `isEdited`,
  `isDeleted`를 포함한다.

## 프론트엔드

공용 `DmReviewCard`의 반응 버튼과 답글 버튼을 하나의 액션 행에 배치한다. 아티클
댓글 목록은 영화 댓글과 같은 공용 카드를 사용하고, 부모 아래에 들여쓴 대댓글을
렌더링한다. 생성·반응 후 SWR 목록을 갱신하며 인증이 없으면 기존 로그인 흐름을
사용한다.

## 오류 처리

- 존재하지 않거나 삭제된 댓글 반응은 404 계열 RPC 오류로 반환한다.
- 다른 사용자의 댓글 수정·삭제는 403으로 거절한다.
- 잘못된 반응 문자열과 2단계 답글은 400으로 거절한다.
- BFF는 인증 누락을 401로 반환하고 서버 오류를 사용자 메시지로 정규화한다.

## 검증

- 서비스 단위 테스트로 반응 토글, 대댓글 생성 제한, 삭제 부모 보존, 수정 상태를 검증한다.
- 저장소/BFF 테스트로 중첩 응답 변환과 OAuth 토큰 전달을 검증한다.
- 프론트 전체 테스트, 린트, 프로덕션 빌드와 200줄 상한을 확인한다.
- 운영 `/articles/4`에서 액션 한 줄, 대댓글, 상태 렌더링과 비로그인 401을 확인한다.
